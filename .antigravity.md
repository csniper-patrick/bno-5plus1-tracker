# Antigravity Workspace Guidelines - BNO 5+1 Tracker

## Project Overview
**bno-5plus1-tracker** is an unofficial, 3rd-party Vue 3 web application designed for UK British National (Overseas) (BNO) visa holders to track, calculate, and manage their travel absence days, qualifications, continuous residence evidence, and address history on the "5+1" route toward Indefinite Leave to Remain (ILR / Settlement) and British Citizenship (Naturalisation).

*Note: This application is an independent 3rd-party tool provided for personal tracking purposes only. It is not affiliated with, endorsed by, or connected to the UK Home Office or UK Government.*

### Key Regulations & Application Data Tracked
1. **Full-Day Absence Rule**: Departure (start) and return (end) dates are partially spent in the UK and are excluded. Only complete 24-hour calendar days spent entirely abroad count as days absent.
2. **Rolling 12-Month Limit & 5-Year Sliding Window (ILR)**: Maximum **180 days** absent in any continuous rolling 365-day period during the 5-year qualifying period. If the 180-day rule cannot be satisfied within the baseline 5 years, the qualifying period automatically shifts/delays forward to the earliest subsequent compliant 5-year window, flagged with a yellow **"Delayed"** warning and active period peak scanning.
3. **5-Year Qualifying Period & Visa Expiry**: Calculated from BNO Visa Start Date or initial UK Arrival Date. Supports an optional **Visa Expiry Date** (defaults to 5 years after visa start), catering to 30-month initial visas or custom extensions, and displaying extension warning alerts if visa expiry precedes the earliest ILR settlement date.
4. **Auto UK Arrival Sync**: Automatic generation/updating of initial arrival absence record if UK Arrival Date > BNO Visa Start Date.
5. **Earliest ILR Application Date**: Applications can be submitted up to **28 days** prior to completing the 5-year continuous residence requirement.
6. **Naturalisation Chaining & Absence Limits**:
   - Baseline Naturalisation target date automatically inherits `ilrTargetDate + 1 year` when ILR is delayed (or uses explicit `ilrApprovedDate` when available).
   - Maximum **450 days** absent in the 5 years prior to naturalisation application.
   - Maximum **90 days** absent in the final 12 months prior to naturalisation application.
   - Physical Presence Requirement: Applicants must be physically present in the UK on the exact date 5 years prior to application. If the start date falls on an absent day, the start date automatically shifts to the earliest subsequent day present in the UK.
7. **Life in the UK & English Language (B1) Tests**: Status, test dates, test centers, unique reference numbers (URN), and qualification pathways.
20: 8. **5-Year Continuous Residence Checklist**: Supporting evidence checklists (Council tax, P60s, bank statements, utilities) structured across Years 1 to 5.
21: 9. **UK Address History Log**: Full residential address entries (Move-in/out dates, postcode, tenure type) required for Home Office SET(O) and Naturalisation AN applications.
22: 10. **Document Vault & Binary Blob Persistence**: Drag-and-drop file storage (PDFs, scans, photos up to 10 MB), organized into category/year folders (`Year 1-5`, `Life in UK`, `English B1`, `Addresses`, `Other`), linked directly to continuous residence checklist items, with inline image/PDF previews and IndexedDB blob persistence.
23: 11. **Unified ZIP Backup & Flexible Import**: One-click export packaging structured data (`backup.yaml`), file manifest index (`files-manifest.yaml`), and binary document files in a folder hierarchy (`files/<folderId>/<filename>`). Import handles both `.zip` archives and standalone `.yaml` files.

85: ## Key Concepts & Architecture
86: 
87: ### 1. `AbsenceSegmentTree` Data Structure ([segmentTree.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/utils/segmentTree.js))
88: To evaluate arbitrary date ranges efficiently over a 10-year period (up to 3,653 days):
89: - A **1-indexed Segment Tree** backed by a `TypedArray` (`Int32Array` of size `4 * N + 1`, 0th index unused) with standard binary child node formulas (`leftNode = 2 * node`, `rightNode = 2 * node + 1`).
90: - **Leaf Map & Fast Point Access**: Stores pre-calculated leaf node indices in `leafMap`. Provides $O(1)$ point queries via `queryPoint(idx)` utilizing `_getLeafNode(idx)` with bounds checking.
91: - **Sliding Window Optimization**: Enables $O(1)$ constant-time sliding window updates in `useAbsentsStore` (`max12MonthAbsenceInfo` & `naturalizationQualifyingPeriod`) by subtracting exiting days (`queryPoint(i - 1)`) and adding entering days (`queryPoint(i + 364)`).
92: - **Range Updates & Interval Building**: Range updates traverse leaves in $O(D \log N)$ time (where $D = \text{endIdx} - \text{startIdx} + 1$ is the range length in days) via `updateRange(qstart, qend, val)` and `build(intervals, val)`.
93: - **Range Queries**: $O(\log N)$ range sum queries for fast computation of absent days in any custom date interval or rolling window via `query(qstart, qend)`.
94: - **Leaf Coverage Array**: An `Int32Array` (`leafCover`) tracks trip coverage count per leaf index, ensuring leaf values in `tree` transition between `0` and `1` accurately when adding or deleting overlapping trips.
95: 
96: ### 2. Centralized Date Utilities ([date.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/utils/date.js))
97: - **`parseDateUTC(input)` / `formatDateUTC(dateObj)` / `normalizeDate(val)`**: Prevents timezone offset shifts by strictly converting inputs to UTC midnight Date objects.
98: - **`calculateDays(startDateStr, endDateStr)`**: Full 24-hour day calculations excluding departure & return days.
99: 
100: ### 3. IndexedDB Binary Blob Storage & Schema Migration ([dbService.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/services/dbService.js) & [fileStorageService.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/services/fileStorageService.js))
101: - **Schema Version 2**: `dbService.js` manages DB upgrades from v1 → v2, creating a dedicated `files` object store with `keyPath: 'id'` and an index on `folderId`.
102: - **Binary Blob Storage**: `fileStorageService.js` handles saving and loading raw file `ArrayBuffer` data, creating temporary Blob Object URLs for inline previews/downloads, updating metadata, and enforcing a 10 MB per-file limit.
103: 
104: ### 4. ZIP & YAML Backup Services ([backupService.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/services/backupService.js) & [zipService.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/services/zipService.js))
105: - **ZIP Archiving**: `zipService.js` packages `backup.yaml` (full application state), `files-manifest.yaml` (file metadata index), and binary document files inside a `files/<folderId>/<filename>` folder hierarchy.
106: - **Flexible Import**: Auto-detects ZIP archives vs standalone YAML files, restoring absence logs, visa dates, qualifications, address history, and reconstructing document file blobs into IndexedDB.
107: 
108: ### 5. Document & Qualification Store ([documents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/documents.js))
109: Manages non-absence settlement requirements and document vault metadata:
110: - **Storage Key**: `bno_tracker_documents_v1`
111: - **Data Sections**: `lifeInUk`, `englishTest`, `residenceChecklist` (Years 1-5), `addressHistory`, `uploadedFiles`, `folders`.
112: - **Address Sorting**: `sortAddresses` automatically maintains chronological order by move-in date.
113: - **File Metadata Hydration**: Hydrates `uploadedFiles` metadata array from IndexedDB on startup without loading full binary blobs into memory until requested.

## Developer & Agent Guidelines

1. **Date Format & Handling**: Always work with standard `YYYY-MM-DD` strings for input dates. Use UTC dates (`parseDateUTC`) when indexing into the Segment Tree array to prevent timezone shifts.
2. **Segment Tree Synchronization**: When altering absence state in `useAbsentsStore`, ensure the segment tree is updated via helper functions (`addRecordToSegmentTree` / `removeRecordFromSegmentTree` / `rebuildSegmentTree`) to keep range queries accurate.
3. **UI & Action Menu Consistency**: Maintain Vuetify 3 component styling and use 3-dots vertical action menus (`v-menu` with `mdi-dots-vertical` activator and compact `v-list`) for table row actions across all views.
4. **Theme Support**: Ensure dark/light themes are respected using Vuetify's `useTheme()` hook and Union Jack palettes defined in `src/plugins/vuetify.js`.
5. **No Direct State Mutation outside Store**: Components should interact with data exclusively through store methods and computed properties.
6. **3rd-Party App Designation & Phrasing**: Maintain clear designation that this is an unofficial 3rd-party application. Avoid using "Home Office Compliant" or official certification wording; use "Rules-Aligned" or "Within Limit" terminology. Keep drawer navigation titles concise ("Absence", "Document") under the "Trackers" section.
7. **Internationalization (i18n) & Key Parity**: Keep `src/locales/en.js` and `src/locales/zh-HK.js` 1-to-1 synchronized in key structure. When using `$te(path)` for checking nested object keys in `vue-i18n`, always pass a leaf key path (e.g. `$te('${i18nPath}.title')`) rather than an object container path. Use `<i18n-t>` component tags for interpolation with dynamic markup slots (`#code`, `#days`, etc.).
