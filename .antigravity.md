# Antigravity Workspace Guidelines - BNO 5+1 Tracker

## Project Overview
**bno-5plus1-tracker** is a high-performance Vue 3 web application designed for UK British National (Overseas) (BNO) visa holders to track, calculate, and manage their absence days from the UK on the "5+1" route toward Indefinite Leave to Remain (ILR / Settlement) and British Citizenship.

### Key Regulations Tracked
1. **Full-Day Absence Rule**: Departure (start) and return (end) dates are partially spent in the UK and are excluded. Only complete 24-hour calendar days spent entirely abroad count as days absent.
2. **Rolling 12-Month Limit**: Maximum **180 days** absent in any continuous rolling 12-month period during the 5-year residency qualifying period for ILR.
3. **5-Year Qualifying Period**: Calculated from the BNO Visa Start Date or initial UK Arrival Date.
4. **Auto UK Arrival Sync**: Automatic generation/updating of initial arrival absence record if UK Arrival Date > BNO Visa Start Date.

## Key Concepts & Architecture

### 1. `AbsenceSegmentTree` Data Structure ([absents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/absents.js#L23))
To evaluate arbitrary date ranges efficiently over a 10-year period (up to 3,653 days):
- A **Segment Tree** backed by a `TypedArray` (`Int32Array`) is constructed.
- **Point Updates**: $O(\log N)$ point updates when adding, updating, or deleting absence records.
- **Range Queries**: $O(\log N)$ range sum queries for fast computation of absent days in any custom date interval or rolling 12-month window.

### 2. Absence Logic & Data Persistence
- **Storage Keys**:
  - `bno_absences`: List of absence records (`id`, `startDate`, `endDate`, `dest`, `isAutoArrival`).
  - `bno_visa_start_date`: User's BNO Visa Start Date (`YYYY-MM-DD`).
  - `bno_uk_arrival_date`: User's UK Arrival Date (`YYYY-MM-DD`).
- **Calculation Rules & UI Validations**:
  - Departure and arrival dates do not count toward full-day absences ($\text{days} = \max(0, \Delta\text{days} - 1)$).
  - Absence Record Editor enforces chronological input bounds: valid departure dates automatically populate as `:min` for the return date picker.
  - Chronological sorting is maintained automatically upon insertion and updates.

### 3. Key Store Actions & Getters ([absents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/absents.js#L147))
- `setVisaAndArrivalDates({ visaStartDate, ukArrivalDate })`: Updates visa/arrival dates and recalculates target settlement dates and arrival records.
- `addAbsence(record)`: Adds a new absence entry and updates segment tree.
- `updateAbsence(record)`: Updates existing entry and refreshes segment tree.
- `deleteAbsence(id)`: Removes record by ID.
- `importData(records, visaStartDate, ukArrivalDate)`: Bulk import of JSON data.
- `exportJSON()` / `exportCSV()`: Data export utilities.
- `maxRolling12MonthAbsence`: Computed property checking all 365/366-day windows across 5 years.
- `yearlyAbsences`: Breakdown of days absent per year for Year 1 through Year 5.

## Developer & Agent Guidelines

1. **Date Format & Handling**: Always work with standard `YYYY-MM-DD` strings for input dates. Use UTC dates (`parseDateUTC`) when indexing into the Segment Tree array to prevent timezone shifts.
2. **Segment Tree Synchronization**: When altering absence state in `useAbsentsStore`, ensure the segment tree is updated via helper functions (`updateSegmentTreeForRecord` / `rebuildSegmentTree`) to keep range queries accurate.
3. **UI Consistency**: Maintain Vuetify 3 component usage (`v-card`, `v-chip`, `v-btn`, `v-dialog`, `v-alert`, `v-table`, `v-text-field`, `v-col`, `v-row`).
4. **Theme Support**: Ensure dark/light themes are respected using Vuetify's `useTheme()` hook.
5. **No Direct State Mutation outside Store**: Components should interact with absence data through store methods and computed properties.
