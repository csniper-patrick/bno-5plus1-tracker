# Antigravity Workspace Guidelines - BNO 5+1 Tracker

## Project Overview
**bno-5plus1-tracker** is an unofficial, 3rd-party Vue 3 web application designed for UK British National (Overseas) (BNO) visa holders to track, calculate, and manage their travel absence days, qualifications, continuous residence evidence, and address history on the "5+1" route toward Indefinite Leave to Remain (ILR / Settlement) and British Citizenship (Naturalisation).

*Note: This application is an independent 3rd-party tool provided for personal tracking purposes only. It is not affiliated with, endorsed by, or connected to the UK Home Office or UK Government.*

### Key Regulations & Application Data Tracked
1. **Full-Day Absence Rule**: Departure (start) and return (end) dates are partially spent in the UK and are excluded. Only complete 24-hour calendar days spent entirely abroad count as days absent.
2. **Rolling 12-Month Limit (ILR)**: Maximum **180 days** absent in any continuous rolling 365-day period during the 5-year residency qualifying period for ILR.
3. **5-Year Qualifying Period**: Calculated from the BNO Visa Start Date or initial UK Arrival Date.
4. **Auto UK Arrival Sync**: Automatic generation/updating of initial arrival absence record if UK Arrival Date > BNO Visa Start Date.
5. **Earliest ILR Application Date**: Applications can be submitted up to **28 days** prior to completing the 5-year continuous residence requirement.
6. **British Citizenship (Naturalisation) 5-Year Limit**: Maximum **450 days** absent in the 5 years immediately preceding application.
7. **British Citizenship (Naturalisation) Final 12-Month Limit**: Maximum **90 days** absent in the final 12 months immediately preceding application.
8. **Physical Presence Requirement**: Applicants must be physically present in the UK on the exact date 5 years prior to the naturalisation application date. If the baseline window start date falls on an absent day, the start date automatically shifts to the earliest subsequent day present in the UK.
9. **Life in the UK & English Language (B1) Tests**: Status, test dates, test centers, unique reference numbers (URN), and qualification pathways.
10. **5-Year Continuous Residence Checklist**: Supporting evidence checklists (Council tax, P60s, bank statements, utilities) structured across Years 1 to 5.
11. **UK Address History Log**: Full residential address entries (Move-in/out dates, postcode, tenure type) required for Home Office SET(O) and Naturalisation AN applications.

## Tech Stack & Dependencies
- **Framework**: Vue 3 (Options API for `AbsenceView.vue` & `DocumentView.vue`, Composition API `<script setup>` for `App.vue` & `ReloadPrompt.vue`)
- **State Management**: Pinia (`useAbsentsStore` in `absents.js`, `useDocumentsStore` in `documents.js`)
- **UI Framework**: Vuetify 3 (`vuetify`, `@mdi/font`) with 3-dots vertical action menus (`v-menu`) on table rows
- **PWA & Caching**: Progressive Web App via `vite-plugin-pwa` with `ReloadPrompt.vue` component
- **Build System**: Vite 8 with `@vitejs/plugin-vue`, `vite-plugin-vuetify`, `@vitejs/plugin-vue-jsx`
- **Routing**: Vue Router 5 (`/` for Absence Tracker, `/documents` for Document Tracker)
- **YAML Engine**: `yaml` package (`Document`, `parse`) for commented YAML backups
- **Formatter**: Prettier 3

## Key Concepts & Architecture

### 1. `AbsenceSegmentTree` Data Structure ([absents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/absents.js#L29))
To evaluate arbitrary date ranges efficiently over a 10-year period (up to 3,653 days):
- A **1-indexed Segment Tree** backed by a `TypedArray` (`Int32Array` of size `4 * N + 1`, 0th index unused) with standard binary child node formulas (`leftNode = 2 * node`, `rightNode = 2 * node + 1`).
- **Point Updates**: $O(\log N)$ point updates when adding, updating, or deleting absence records via `addRecordToSegmentTree` and `removeRecordFromSegmentTree`.
- **Range Queries**: $O(\log N)$ range sum queries for fast computation of absent days in any custom date interval or rolling 12-month window.
- **Coverage Array**: An `Int32Array` tracks trip coverage per day index, ensuring tree leaves are updated to `0` or `1` only when total coverage transitions between 0 and non-zero.

### 2. Document & Qualification Store ([documents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/documents.js))
Manages non-absence settlement requirements:
- **Storage Key**: `bno_tracker_documents_v1`
- **Data Sections**: `lifeInUk`, `englishTest`, `residenceChecklist` (Years 1-5), `addressHistory`.
- **Address Sorting**: `sortAddresses` automatically maintains chronological order by move-in date.

### 3. Consolidated Navigation & Backup Drawer ([App.vue](file:///Users/csniper/Projects/bno-5plus1-tracker/src/App.vue))
- Right-side `<v-navigation-drawer location="right">` controlled by a top bar hamburger button (`mdi-menu`).
- **Export All Data (YAML)**: Generates a single backup file containing both absences and document tracker state, formatted with inline node-level comments using `Document` from `yaml`.
- **Import Data (YAML)**: Restores all application state into `useAbsentsStore` and `useDocumentsStore`.
- **Clear All Data**: Global reset confirmation modal clearing all store states.

## Developer & Agent Guidelines

1. **Date Format & Handling**: Always work with standard `YYYY-MM-DD` strings for input dates. Use UTC dates (`parseDateUTC`) when indexing into the Segment Tree array to prevent timezone shifts.
2. **Segment Tree Synchronization**: When altering absence state in `useAbsentsStore`, ensure the segment tree is updated via helper functions (`addRecordToSegmentTree` / `removeRecordFromSegmentTree` / `rebuildSegmentTree`) to keep range queries accurate.
3. **UI & Action Menu Consistency**: Maintain Vuetify 3 component styling and use 3-dots vertical action menus (`v-menu` with `mdi-dots-vertical` activator and compact `v-list`) for table row actions across all views.
4. **Theme Support**: Ensure dark/light themes are respected using Vuetify's `useTheme()` hook and Union Jack palettes defined in `src/plugins/vuetify.js`.
5. **No Direct State Mutation outside Store**: Components should interact with data exclusively through store methods and computed properties.
6. **3rd-Party App Designation & Phrasing**: Maintain clear designation that this is an unofficial 3rd-party application. Avoid using "Home Office Compliant" or official certification wording; use "Rules-Aligned" or "Within Limit" terminology. Keep drawer navigation titles concise ("Absence", "Document") under the "Trackers" section.
