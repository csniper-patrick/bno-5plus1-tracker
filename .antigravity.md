# Antigravity Workspace Guidelines - BNO 5+1 Tracker

## Project Overview
**bno-5plus1-tracker** is a high-performance Vue 3 web application designed for UK British National (Overseas) (BNO) visa holders to track, calculate, and manage their absence days from the UK on the "5+1" route toward Indefinite Leave to Remain (ILR / Settlement) and British Citizenship (Naturalisation).

### Key Regulations Tracked
1. **Full-Day Absence Rule**: Departure (start) and return (end) dates are partially spent in the UK and are excluded. Only complete 24-hour calendar days spent entirely abroad count as days absent.
2. **Rolling 12-Month Limit (ILR)**: Maximum **180 days** absent in any continuous rolling 365-day period during the 5-year residency qualifying period for ILR.
3. **5-Year Qualifying Period**: Calculated from the BNO Visa Start Date or initial UK Arrival Date.
4. **Auto UK Arrival Sync**: Automatic generation/updating of initial arrival absence record if UK Arrival Date > BNO Visa Start Date.
5. **Earliest ILR Application Date**: Applications can be submitted up to **28 days** prior to completing the 5-year continuous residence requirement.
6. **British Citizenship (Naturalisation) 5-Year Limit**: Maximum **450 days** absent in the 5 years immediately preceding application.
7. **British Citizenship (Naturalisation) Final 12-Month Limit**: Maximum **90 days** absent in the final 12 months immediately preceding application.
8. **Physical Presence Requirement**: Applicants must be physically present in the UK on the exact date 5 years prior to the naturalisation application date. If the baseline window start date falls on an absent day, the start date automatically shifts to the earliest subsequent day present in the UK.

## Key Concepts & Architecture

### 1. `AbsenceSegmentTree` Data Structure ([absents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/absents.js#L29))
To evaluate arbitrary date ranges efficiently over a 10-year period (up to 3,653 days):
- A **Segment Tree** backed by a `TypedArray` (`Int32Array`) is constructed.
- **Point Updates**: $O(\log N)$ point updates when adding, updating, or deleting absence records via `addRecordToSegmentTree` and `removeRecordFromSegmentTree`.
- **Range Queries**: $O(\log N)$ range sum queries for fast computation of absent days in any custom date interval or rolling 12-month window.
- **Coverage Array**: An `Int32Array` tracks trip coverage per day index, ensuring tree leaves are updated to `0` or `1` only when total coverage transitions between 0 and non-zero (preventing double counting of overlapping trips).

### 2. Absence Logic & Data Persistence
- **Storage Keys**:
  - `bno_absences`: List of absence records (`id`, `startDate`, `endDate`, `dest`, `isAutoArrival`).
  - `bno_visa_start_date`: User's BNO Visa Start Date (`YYYY-MM-DD`).
  - `bno_uk_arrival_date`: User's UK Arrival Date (`YYYY-MM-DD`).
  - `bno_ilr_approved_date`: User's ILR Approved Date (`YYYY-MM-DD`), used to calculate the 5-year naturalisation window.
- **Calculation Rules & UI Validations**:
  - Departure and arrival dates do not count toward full-day absences ($\text{days} = \max(0, \Delta\text{days} - 1)$).
  - Absence Record Editor enforces chronological input bounds: valid departure dates automatically populate as `:min` for the return date picker.
  - Naturalisation 5-Year Window: Default baseline start is 1 year post-`visaStartDate`. If `ilrApprovedDate` is set, baseline start is 4 years prior to `ilrApprovedDate` (ending 1 year post-ILR). In both cases, start dates falling on absent days shift to the next day present in the UK.
  - Chronological sorting is maintained automatically upon insertion and updates.

### 3. Key Store Actions & Getters ([absents.js](file:///Users/csniper/Projects/bno-5plus1-tracker/src/stores/absents.js#L215))
- `setVisaAndArrivalDates({ visaStartDate, ukArrivalDate, ilrApprovedDate })`: Updates key dates and recalculates target settlement/naturalisation dates.
- `addAbsence(record)`: Adds a new absence entry and incrementally updates the segment tree.
- `updateAbsence(id, fields)`: Updates existing entry and refreshes segment tree.
- `removeAbsence(id)`: Removes record by ID.
- `importYAML(yamlString)`: Bulk import of YAML data including key dates.
- `exportYAML()`: Exports key dates and absence entries to YAML format.
- `max12MonthAbsenceInfo`: Computed property scanning rolling 365-day windows across 5+ years to find peak absence duration and peak window dates `{ maxDays, peakStartDate, peakEndDate }`.
- `naturalization5YearAbsence` & `naturalizationFinal12MoAbsence`: Computed properties for Naturalisation compliance checks.

## Developer & Agent Guidelines

1. **Date Format & Handling**: Always work with standard `YYYY-MM-DD` strings for input dates. Use UTC dates (`parseDateUTC`) when indexing into the Segment Tree array to prevent timezone shifts.
2. **Segment Tree Synchronization**: When altering absence state in `useAbsentsStore`, ensure the segment tree is updated via helper functions (`addRecordToSegmentTree` / `removeRecordFromSegmentTree` / `rebuildSegmentTree`) to keep range queries accurate.
3. **UI Consistency**: Maintain Vuetify 3 component usage (`v-card`, `v-chip`, `v-btn`, `v-dialog`, `v-alert`, `v-table`, `v-text-field`, `v-col`, `v-row`).
4. **Theme Support**: Ensure dark/light themes are respected using Vuetify's `useTheme()` hook and Union Jack palettes defined in `src/plugins/vuetify.js`.
5. **No Direct State Mutation outside Store**: Components should interact with absence data exclusively through store methods and computed properties.
